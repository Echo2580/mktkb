## 2 入账收口 / 不双重计数（静态）
- 四分支（失败结算、零付费、usage 缺失、成功结算）在 :1477 统一 `settled_cny += charged_cny` 一次，
  `settled_booked=True`；成功分支不再各自累加（diff 删除了 3 处旧 `settled_cny +=`）。
- 异常分支只在 `j1_settle and not settled_booked` 时补记一次（:1487）；
  若成功结算已入账后又在同一 try 内抛错，`settled_booked` 阻止第二次累加。
- 成功计数 `settled_success += 1` 在 `settle_success` 返回之后（:1472）；异常时不会加。
- `by_center_cny` 在正常路径 :1483-1485、异常补记路径 :1497-1499 各加一次，均以同一 charged 金额为准。
- 混合轮 probe：settled_success(0.000384) + rejected(0.018688) = 0.019072 = summary held
  = 两行 charged_cny 之和；requests_sent=1。未出现"成功额被重复计入 rejected"。

## 3 旧键语义
- 正常轮：修复前后 held 0.000508、settled_cny 0.000384、requests_sent 1、provider_billed 0.000508 全同。
- 仅在被拒轮，原先漏记的 0.018688 现在进入 settled_cny/by_center/conservative_held；
  这正是 §7.2 对 `conservative_held_cny` 的既有定义（"已写 result 的保守占用"）的恢复，
  不是把该笔冒充成"供应商已计费"`（provider_billed_cny 仍不含它）。
- 兼容键 settled_failure=failed_rounds、unused_no_paid_attempt=unpaid_rounds、billed_cny 实测口径均未改。

## 4 残余风险 / 与契约的边界（非本次 C1 场景，供经理决定）
R1（中等，建议后续收紧）：`except Exception` + `j1_settle` 假定"门已写 result"。
  真实 `P2Gate.settle_success` 有两类异常发生在写账本之前：
  - evidence 不是 UsageEvidence -> P2GateError("evidence_required")（p2_authorization.py:1178-1179）；
  - OCR 估算额越界 -> P2GateError("estimate_out_of_bound")（:1193-1194）；
  另有 rag/budget.py:776-789 的 BudgetLedgerInvalid（找不到预留/重复结算/绑定不一致）也在写 result 前抛出。
  若调用方用真实门但没注入 settle_evidence（run_p2 签名允许，p2_runner.py:728），runner 现在会把
  "无账本 result"的这笔也按上界计入 rejected_rounds/conservative_held，造成相对账本"虚增"，
  与 §7.2 的"门内账本已经写 result"前提不符。正常 live 入口 run_live_p2 总是注入
  make_settle_evidence（p2_live.py:1391），故实测路径未触发；建议只对
  SettlementNotReleasable/SettlementBoundaryAnomaly（或已知写后抛错的 reason）补记，
  或先核对门账本确有该 reservation 的 result。
R2（文档小瑕）：_money_split docstring 的关系句（p2_runner.py:1090-1091）仍写
  "差额（held - provider_billed）= 零付费轮 + 失败轮"，未加 J1 拒绝轮；report §2 称
  "_money_split 注释同步"只对了一半。不影响行为与契约 §7.2。
R3（口径提醒）：`run_result.settled_cny` 是 answer 单侧"已入账保守额"，不是"供应商账单"；
  本合同已用 provider_billed_cny 区分。下游若把它当已计费金额会误读，但这在 FIX-B 三口径时已声明。
R4（测试层面）：runner 单测的 _RejectingGate 是桩门、不写账本，无法证明"summary == 账本"；
  该项由 live 用例（真实 P2Gate）覆盖，probe 亦独立复核，故不构成缺口。
