## 结论（03）
- B：真实 P2Gate + 真实 DeepSeek/Bailian/OCR 编解码，一次完整回合 -> 5 笔预留 / 5 条结果 /
  4 条从属尝试回执（index×2、query_embedding、rerank）+ answer；中心全部 answer_retrieval；
  gate_reserved=expected=5；outbound=0（mock_intercepted=5）；answer 按 64/32 token 结算 0.000384。
- C：缺 chat usage -> usage_evidence_missing，answer 预留按 0.018688 保守占用并停，不伪造金额。
- D：**计划项配额按 embed() 调用计，不按底层 HTTP 请求计**：ingest 计划项 requests=1，
  但 D01 的文本被 `embedding_batch_size=5` 拆成 2 次 POST -> 2 笔 index_embedding 预留且未触发
  attempt_quota_exhausted。同一探针的计数复核（同一 run）：
  `wiring.embedding_calls=2`（1 次灌库 + 1 次查询）、`attempt_budget.used{'ingest-index-embedding': 1}`、
  `embedding transport calls=3`、`index_embedding 预留=2` -> 一次 embed 调用产生 2 笔预留、只消耗 1 次配额。
- E1：record 型问题在空库下 0 次 chat 调用，answer 预留走 close_unused（0.018688、不停止）。
- E2：**正文型问题在空库下真的发出一次 query_expansion chat**（chat purposes={'query_expansion': 1}），
  但该笔被记在 `answer-V01-t1` 上（计划里另有 `expand-V01-t1` 项从未使用），
  并以 succeeded/0.000384 结算 —— 与 p2-live-binding §10.5(2)「产品当前检索路径没有
  query expansion 调用」矛盾。
- I：OCR 走真实 TencentOCRClient：TC3-HMAC-SHA256、GeneralAccurateOCR、host=ocr.tencentcloudapi.com；
  每页 1 笔 ocr 预留（中心 ocr、0.5），第二页 attempt_item_exhausted 且无额外出站。
