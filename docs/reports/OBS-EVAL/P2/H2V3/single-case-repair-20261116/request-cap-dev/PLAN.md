# 累计请求上限实现计划

目标：P2 显式无限请求次数贯通计划、GO、预检、授权、绑定、逐笔账本；金额、单项次数和所有其他授权约束不变。

设计：使用 JSON 字符串 `unlimited` 明确表示无限；有限正整数保留旧语义及既有硬顶。计划和 GO 必须都显式无限才得到无限授权，混合时按有限侧约束并对计划超出 GO 的情况拒绝。账本默认及 P1 仍有限；只有明确传入该值且经逐笔守卫复核才能无限。缺字段、布尔、负数、其他字符串和非有限数字均拒绝。报告中的无限剩余同样使用 `unlimited`，绝不使用巨大整数。

1. 先保存已有修改、数量相关文件与预算账本哈希；仅使用合成数据写红例，启用禁止联网和 dotenv 的守卫。
2. 修改 P2 合同、授权和共享账本的数量类型、计算与逐笔复核；保持金额及计划约束不变。
3. 修改 H2 v3 计划、绑定、CLI 与输出中数量的表示，检查 runner 的序列化消费点；旧入口继续有限。
4. 针对大于 1500/1600 的历史计数运行预检、预留、发送与结算；覆盖旧有限 GO、非法输入、四种金额边界、有限模式和往返；执行必要相关回归。
5. 保存命令、收集结果、退出码、零出站守卫证明、前后哈希及增量差异；说明任何未验证项，不调用真实服务、不修改真实账本或 GO。
