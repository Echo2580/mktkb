# 主人需决定：四类硬失败的语义归属保管

## 当前具体缺口

只读审计 hard-evidence-feasibility.md 确认：冻结CaseSpec有should_refuse、refusal_reason和禁用值/来源，但没有四维适用性/语义归属的正式字段。无资料拒答不天然是安全，source_hit失败不天然是跨实体，普通正文也不天然无实体约束。当前程序必须保留unknown；不能靠新增checked布尔或加密verdict宣称四类0。

当前交接限制经理/开发/验收只看安全聚合，真实题面/答案/逐题观测仅在受控进程使用。以下方案会允许两个专门保管角色在隔离模型上下文中看到冻结题面和标注，因此需主人对这项可见性例外明确决定，不能把现有修复授权当成私自开放H2原文。

## 建议授权的具体范围

1. 新建独立“保管标注”角色与另一独立“保管复核”角色（使用当前可用内置助手，非旧wb入口）；只这两个隔离上下文可读取现有冻结H2题面/原标签及本次保管附件。它们不得读取真实运行回答/逐题trace，不改题干、参考答案、expected kind/value/source、30题或阈值。
2. 补充独立、版本化的四轴附件：每题每轴仅登记 applicability(pass适用或not_applicable或unknown)、固定criterion/reason code及已有冻结refs指向的目标身份/日期范围。不得按产品输出/分数改适用性，不得因难判而选N/A；不满足证据就unknown。
3. 附件只在受控本机进程中序列化并加密，写工作区外本会话授权目录；密钥只由既有受控loader读取、不输出。经理/开发/验收只见整体hash、计数、缺口和公共分类规则；题号/题面/答案/逐题附件不回传主会话、不入仓库。
4. 第二保管角色独立对照冻结H2复核附件，任意不一致即返工/unknown；冻结附件hash后才交受控运行进程使用。此步骤只补语义归属，不证明真实产品通过。
5. 另行实现并独立验收实际请求/会话owner/来源有效状态/实体/日期的受控快照与确定性分类；真实运行审计可仓外加密保全，由另一受控进程内存解密重算，只出安全聚合，不再调用模型。原始凭据、密码hash、session token、HTTP认证头不采集。
6. 仍必须真实全30、≥24、错误/未执行0、四类硬失败0且unknown0/证据可核；gate不擅自approved，不进入T208/T209/T900，不增加40/20元和既有中心/请求限额。

本方案尚未读取或开放任何真实H2原文，尚未生成附件或新的真实调用。它补的是语义归属证据，不能替代实际产品修复或独立质量复核。

## 主人决定（2026-11-12接续确认）

主人在本会话明确选择“授权专门保管标注与复核（推荐）”。以上两个专门保管角色的隔离原文可见性例外已获授权；经理、开发和验收的聚合边界不变。此授权不等于已完成标注/复核/真实验证，不允许读取或调整真实运行回答来标注。

## 保持现有边界的选择

不允许任何新保管角色看到冻结原文：继续程序可核的离线修复与受控验证；无法确定的安全/自由正文实体语义保持unknown，T207完整质量不能据此通过。不会以恒0或N/A替代证据。
