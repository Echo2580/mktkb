## 1. 环境、账号与费用（先做这一步）

### 1.1 启动（真实版本）

```bat
:: 必须开一个命令行窗口，先设数据目录，再在同一窗口里调用脚本（不要直接双击 .cmd，否则数据目录会落到仓库 var\）
set MKTKB_DATA_DIR=D:\mktkb-p2-ua\data
一键启动.cmd
```

- **必须**在同一窗口 `set` 后运行 `一键启动.cmd`；脚本自己会设置真实参数（`MKTKB_RAG_PROVIDER_MODE=live`、`deepseek-flash`、OCR 开启、阶段 `S2-OWNER-ACCEPTANCE`）。

## 2. 判分与记录纪律（执行人必读）

### 2.1 四态判定

| 判定 | 含义 |
| --- | --- |
| `PASS` | 实际行为与"预期"逐项相符，且证据齐全 |
| `FAIL` | 实际行为与预期不符（含：答错、编造、该拒答却作答、该答却拒答、越权成功、崩溃、文案误导） |
| `BLOCKED` | 前置条件不满足导致无法判定（环境没起来、额度不足、资料处理失败等）；必须写清缺什么 |
| `NOT-RUN` | 本轮没执行；必须写原因（预算、授权、时间），**不得用 PASS 代替** |

### 2.2 三分类（写进"现象"列，不要混）

- **产品缺陷**：产品自身行为错（检索、判定、文案、权限、状态机）。
- **服务与环境**：上游模型/OCR 超时、网络、磁盘、内存等外部原因（记录错误码与时间）。
- **观察项**：体验/措辞/性能等，不构成缺陷但值得记。

### 2.3 每题必须留的五要素 + 三附加

`提问原文 / 返回 kind / 答案原文 / 来源文件名（有/无） / error_code（有/无）`，
外加 `会话第几轮（是否新会话） / 实际耗时 / 截图路径`。

- 判定"答对"看**要点**不看措辞；同一题两次句式不同不影响判定。
- 答案里出现资料中没有的数字/事实 = 错（**幻觉比漏答严重**）。
- 有答案但来源为空 = 错。
- 标准答案是"有"却返回 `not_found` = 错；标准答案是"无"却编出答案 = 错。
- 遇 500/白屏：保留后端控制台 traceback 全文（唯一定位线索）+ 截图 + 请求时间。

### 2.4 红线

1. **不许改代码、改配置、改数据、清账、合并分支**。测试期间只允许"点界面 + 调只读 API + 上传/发布/删除资料"。
2. **不许把已知限制当缺陷**（见 §9）：例如 H2/U 属于评测面、供应商实账缺失、OCR 7/8 通过。
3. **不许跳过失败**：FAIL 必须原样保留，禁止"重跑一遍看起来好了就记 PASS"（可另记一条复现结果）。
4. **不许在报告里出现口令、API Key、`.env` 内容、原件绝对路径**。
5. 每完成一个测试集，落一次记录表（防丢失）。

- "可以用"的最低线：**A 组主链全通 + B 组无越权 + 40 题 ≥36 且 Q01–Q24 全对 + E 组无"高"级仍复现**。
- 若 E 组任何"高"级问题仍复现（E-01/E-02/E-03/E-04/E-07），即使 40 题达标，结论也只能是
  **"可试用但未达发布质量"**，并单列这 5 条。
- 任何 `FAIL` 都不得用"看起来好了"覆盖；重跑产生的新结果另记一行。

## 11. 已知限制（不许记成缺陷）

1. H2/U/N/C/U 属**评测面**（离线证据链），不是用户功能；用户测试不需要碰。

4. 长会话超过约 12 轮可能触模型上下文上限——属模型侧限制，记为观察项并注明轮次。
5. 冲突资料若产品按"以最新版本为准"并明确说明，属正确行为，不算缺陷。
6. 监控 API 无 UI 页面属设计现状。
