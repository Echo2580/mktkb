# P2 收尾任务 4 · 正式跨场景门禁

**角色**　开发、独立验收、经理接收。任务 2、3 准备期间先定输入契约并做合成验证，避免与任务 1 共写 H2 分类器、与任务 3 共写公共评分器。可复用 [总门判定](../../../backend/src/mktkb/evaluation/p2_scoring.py)、[公开评分与观察矩阵](../../../backend/src/mktkb/evaluation/p2_score_run.py)、[CLI](../../../backend/src/mktkb/evaluation/cli.py) 和 [B0 准入证明](../../../backend/src/mktkb/evaluation/p2_b0.py)。

## 实现与验收

1. 增设正式证据入口，显式加载批准配置，并绑定已登记 B0、候选流水线、N/C/U 证据清单和 H2 同批聚合。复用现有评分/身份/严格校验函数，保留三份真实公开 run 的各自身份、U 本地证据、H2 原运行和派生评分器身份。历史证据跨版本时验证其适用性及来源链，保存原摘要。
2. 严格核对 B0 执行 40/40、至少正确 36/40、精确 24/24、OCR 8/8 执行。分别核对 N 8/8、C 6/6、U 10/10（1 真实 smoke、9 本地控制），H2 同批 30 题 36 回合、至少正确 24/30、五层齐全、硬失败 0。八项硬门禁保留各自适用性和最小样本。缺证、未执行、必需未知、硬失败、版本和身份不符均以固定原因阻断。
3. H2 使用严格场景卡和组合校验，再根据受认证的原冻结适用性和受限聚合验证必需未知数。分别展示必需轴、非必需轴、整卡 `verified` 和总门判定。若现有契约缺少可校验的适用性证明，新增绑定原证据的聚合证明契约及负例。C25 保留原非必需未知口径。严禁用调用方自报布尔或名称白名单作为必要证据。
4. 在现行正式配置入口，以齐备合成证据验证门禁可达通过。移除任意一组输入并分别验证拒绝。负例至少覆盖假 B0、跨计划合并、陈旧配置、同版本错摘要、U 重复、H2 v0.1 冒充 v0.2、覆盖缺失、必需未知、伪造适用性、真硬失败以及回执/摘要错配。验证原 B0 准入留存、P1 差异和档案恢复。任务 2、3 就绪后，以真实历史工件只读验证正式入口。
5. 分别展示证据缺失或冲突、质量门结果和主人发布决定。技术门禁通过只作为 T900 独立验收输入。Ragas 作为 T208 辅助诊断，沿用已批准标准。

**交付**　`docs/reports/OBS-EVAL/P2/CROSS-SCENARIO-GATE/report.md`、独立 `review.md`、可复算的脱敏门禁结果及入口命令。定向回归至少覆盖受影响的 `test_p2_gate.py`、`test_p2_score_run.py`、`test_p2_holdout_scenarios.py`、`test_diff_release_gate.py`、`test_baseline_portability.py`。开发与独立回报分别附命令、退出码、版本和未覆盖项。
