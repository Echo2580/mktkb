## 三、执行顺序

1. 环境自检（ENV-1/2/3）→ 记录端口、数据目录、启动方式。
2. **A 组**（管理员功能）：导入 `fixtures/acceptance/normal/` 下 D01–D10 → 等处理完成 → 发布 →
   A-01…A-19。注意：D07/D08/D09/D10 会触发**真实 OCR（约 5.65 元）**，只能导一次。
3. **C 组**：40 题（每题新开会话），记录 kind/答案要点/来源/是否新增事实。
4. **D 组**：场景题（注意哪些要"同会话"、哪些要"新会话"）。
5. **E 组（本次重点）**：P1 遗留专项。E-01/E-05/E-07/E-10 用 D 组语料即可；
   E-02/E-03/E-04/E-06/E-08/E-09 需先按任务书 §7.0 再导入 6 份企业语料并发布（纯文本，不产生 OCR 费用）。
6. **B 组**：员工权限（资料已发布后再做）。
7. **F 组**边界文件 + **G 组**监控 API。

## 四、判定纪律

- 只用四态：`PASS` / `FAIL` / `BLOCKED` / `NOT-RUN`。**没跑就写 NOT-RUN，不许用 PASS 代替。**
- 每条 FAIL 分三分类：**产品缺陷 / 服务与环境 / 观察项**。
- 每题至少留：提问原文、返回 kind、答案原文（截断 200 字）、来源（文件/无）、error_code（有/无）、
  会话轮次、耗时、截图路径。
- 判"答对"看要点不看措辞；**答案出现资料里没有的数字/事实 = 错（幻觉比漏答严重）**；
  有答案无来源 = 错；该答却 not_found = 错；没问过的实体被写进答案 = 错。
- **不许把已知限制当缺陷**：H2/U/N/C/U 是评测面；供应商实账不可得；OCR 通过率 7/8 是历史披露值；
  长会话约 12 轮可能触模型上下文上限（记观察项并注明轮次）；监控无 UI 页面属设计现状。
- 遇到"额度不足"：立刻停，剩余用例标 `BLOCKED（plan_exhausted）` 并交回。
- 遇 500/白屏：保留后端控制台 traceback 全文 + 截图 + 时间，别只截图。

4. 不许自行扩大额度或更换账号测越权以外的用途。

## 七、最后交回给主人的格式（不超过 20 行）
