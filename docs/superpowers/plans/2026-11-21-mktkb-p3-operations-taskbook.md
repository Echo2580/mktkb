# 市场部 AI 知识库 P3・知识运营工作台任务书

**版本目标**　管理员从运营首页发现异常，能下钻到具体问答或导入任务，核对答案、引用资料及版本，并查看已记录的执行阶段与耗时。

**设计依据**　[知识运营数据中台方案](../specs/2026-11-21-knowledge-operations-data-center-design.md)中的首版工作台范围，以及已确认的首页布局和问答耗时条设计。

**起点**　以 [P2 v0.3 重新资格化发布记录](../../reports/OBS-EVAL/P2/FOLLOW-UP/requalification/release-decision.v0_3.md)对应的候选 `7556efd` 为 P2 已发布参照。编制时分支 `codex/p2-e2e` 的 HEAD 为发布记录提交 `cb74457`；独立复核时 HEAD 已前进至 `0d6ba61`，发布后新增 `04515f3`（一键启动 real-first 修复）、`2d4d839`（用户视角验收测试书）、`0d6ba61`（验收计划扩展）三个提交，工作区另有在途改动与未跟踪证据。T301 开始时重核实际分支、基线和工作区，记录实际 HEAD 与发布后提交清单，启动路径变更纳入 T306 启动 / 回退与 P2 回归范围核对，保留在途改动和历史证据。

**实现方式**　沿用 React、TypeScript、FastAPI 和现有 SQLite 数据源，使用 ECharts 绘制总览图表。P3 新增只读查询、管理端页面与验证用例。先用业务库、现有 Trace 和评测摘要支撑页面。

**修订**　2026-11-21 独立复核后小修：更新基线描述；T302 补评测批次列表接口；明确已删除会话与冲突来源口径；T301 必交 Span→阶段映射与评测批次白名单；T306 写明测试命令工作目录与最小 P2 回归集。

## 1. P3 必须交付的功能



| 功能          | 可用结果                                                                                                           |
| ----------- | -------------------------------------------------------------------------------------------------------------- |
| **管理员运营入口** | 现有管理端新增「知识运营」，包含运营总览、问答诊断、知识资产。普通员工的问答和资料使用路径按 P2 权限运行。                                                        |
| **运营总览**    | 默认近 7 天，可切换时间范围。展示已完成问答、未找到、资料冲突、待审核版本，以及问答趋势、六类结果分布和来自现有记录的待处理列表。点某天、某类结果或某条待处理事项，能打开对应明细。                    |
| **问答诊断**    | 按时间及结果筛选。详情展示问题、最终结果、知识库 revision、引用资料及版本。对已记录的检索、重排、生成和校验阶段展示耗时，支持查看多次尝试和无 Trace 状态。已有固定集评测以独立摘要展示批次、样本及指标状态。 |
| **知识资产**    | 按文件类型、版本或处理状态查看资料。展示当前及历史版本、待审核或失败原因、最终引用量和相关问答，可跳到现有资料管理继续核对。                                                 |

后续迭代单列员工反馈与工单、知识缺口聚类、发布后自动回归、条款差异和变更影响、新的候选明细采集、原文高亮及市场台账分析。P3 首发也采用现有部署形态，独立分析平台与数据仓库按后续需求评估。

## 2. 数据口径与权限



* **问答量**按完成时间、产品请求 ID 去重，只计已提交结果的请求。幂等重放不增加数量。六类结果沿用现有契约 `answer`、`clarification`、`not_found`、`conflict`、`service_error`、`knowledge_changed`。按结果统计的图表和下钻列表用同一查询条件。未提交结果的中断单列，不归入六类分布。已逻辑删除会话中的请求在统计与下钻明细中均排除，两侧口径一致。

* **时间与库存**按 `Asia/Shanghai` 显示并聚合。日历日期转为左闭右开的 UTC 窗口。默认近 7 个自然日含今天，支持今日、近 7 天、近 30 天及不超过 90 天的自定义窗口。问答量、引用量和带日期的事件随筛选变化。待审核和生效资料等库存指标标记「当前」，下钻使用相同的当前状态口径。

* **引用量**按「结果消息 + 文档」去重，版本维度按「结果消息 + 版本」去重。同一回答引用同一资料多行只计一次。冲突来源在问答详情分列，资产页的「最终引用」统计正常回答的持久引用。冲突消息不产生持久引用行，两方来源取自结果 JSON 的 conflicts；资产页「相关问答」及按文档或版本过滤问答时包含这类冲突来源并单独标注，「最终引用」计数不含冲突。

* **追踪与评测**按请求关联实际保存的 Trace。覆盖率按筛选范围内「有普通执行 Trace 的已完成请求数 ÷ 已完成请求数」计算，纯重放记录不计为覆盖，读取失败时不报覆盖率。关闭、不可用、未记录和部分覆盖采用独立状态。只渲染实际存在的阶段和耗时，重放可辨认。固定集摘要只读公开或当前权限可查的运行，保留分母和评测状态。线上问答数量和有引用占比均不得标为业务正确率。

* **访问范围**沿用 `admin` 角色。运营列表显示用于排查的摘要，详情按需取当前库未删除问答及可展示的引用元信息。历史或失效引用保留可展示的版本标识，摘录和原件继续受各自现有规则校验。管理员的跨会话诊断权限限定在运营接口，普通会话、引用及原件接口的归属校验不变。禁止运营响应和测试证据输出密钥、原始请求头或 Trace 原始属性。

* **数据与费用**业务数据由正常流程产生，演示可用隔离库中完整执行产生的示例记录并标明环境。业务库和 Trace 库的回填、迁移及性能测试在副本上做。P3 标准验收使用离线执行和受控替身网关，真实模型、OCR、Ragas 裁判调用及部署按已有授权流程单独办理。

| 接口                                               | 合同要点                                                                                                                                  |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |

| `GET /api/v1/operations/requests`                | 按完成时间、结果类型分页，支持文档或版本过滤。确定性排序，以完成时间和请求 ID 为游标。                                                                                         |

## 4. 推进和接收标准

各任务由实施方提交变更、验证证据和已知限制。独立验收按任务的完成条件给出结论，项目经理按证据接收，任务结论及未验证事项进入 `docs/reports/OBS-EVAL/P3/`。使用 `PASS`、`FAIL`、`BLOCKED`、`NOT-RUN` 记录实际状态。开发自测、独立验收和真实环境验证分别列出。

**P3 候选可提请发布的条件**



1. 三个页面与对应查询可用，三个端到端场景均通过独立验收。

2. 时间和类型筛选下，相关汇总数字能从明细复算。无 Trace、无评测结果和未知字段有明确状态。

3. 员工无法访问管理员数据。历史引用、原件访问和既有 P2 问答及资料流程没有发现回归。

4. 候选版本、测过的环境、受控替身范围、待验证事项和回退方式已记录。

首个执行任务为 **T301 基线和数据核对**。本任务书编制阶段仅确认范围与执行顺序。开发和验收结果在后续按实际执行记录。
