# P2 收尾任务 1 · H2 文档级禁源与离线重建接入

**角色**　开发者先完成实现和自测，全新独立窗口复核，经理接收后移交任务 2。只用公开材料与合成数据。发给开发者时一并提供本任务书和[总览](2026-11-20-p2-closeout-taskbooks.md)。

## 输入与范围

C27/C29 的冻结禁源引用只有文档代号。现有匹配器先要求单元定位，且正式离线重建路径未接入可信的场景来源身份。目标是保留冻结判据，用同场景文档身份和版本判断文档级禁源，并能从历史封存重建可校验的派生卡。起点为 [H2 分类与卡校验](../../../backend/src/mktkb/evaluation/p2_hard_evidence.py)、[离线身份匹配](../../../backend/src/mktkb/evaluation/p2_evidence_rescore.py)、[受控重建入口](../../../tools/p2_h2_controlled_execute.py) 及 [H2v3 入口](../../../tools/p2_h2_v3_controlled_execute.py)。

允许修改 H2 证据重建、评分接线和针对性测试。产品问答、冻结题集、标注、官方阈值、历史运行和账本保留。开发窗口使用合成的密文结构和假身份验证，原批次由任务 2 的保管人处理。

## 执行与验收

1. 在正常重建入口复现两个缺口。使用纯文档引用和合成同源、异源、异版本、缺证回合。核定真实历史读取的输入契约与 `code_changed_since_plan` 保护。分别记录原运行代码/计划身份与派生评分器身份，建立只读、可追溯的离线重建路径，保持现有真实执行入口的历史身份检查。
2. 按冻结 source map、场景实际入库映射与已认证使用层证据确定文档和版本。同文档同版本真实使用应判 `forbidden_source_used`，可靠的跨版本或其他文档身份应排除。缺少版本、映射冲突、使用层不完整或空集无证明保持 `unknown`。带 `unit_key` 或 `locator` 的引用沿用定位语义。验证模型证据、直答事实、直答引用及最终引用，单纯检索候选按原适用口径处理。
3. 由合成的四场景封存生成新派生卡。四张卡分别通过 `validate_hard_evidence_scorecard`，组合通过 `validate_hard_evidence_composition` 的结构、绑定和等式校验。用错场景、错计划、错摘要、缺回合、重复题、v0.1 质量聚合及手改 `verified` 作为负例。验证既有非必需未知可如实保留，必需未知仍由正式总门阻断。
4. 自测以 `test_p2_hard_evidence.py`、`test_p2_holdout_scenarios.py`、受控重建和评分入口的受影响用例为主。独立窗口自写至少一个真违规与一个身份不充分的反例，核对零请求和原件保护，并按实际命令、退出码和产物给结论。

**交付**　`docs/reports/OBS-EVAL/P2/H2-DOC-REBUILD/report.md` 和独立 `review.md`。附触发缺口、修改范围、源码摘要、受控重建命令与预期输入字段、脱敏输出格式、正反例结果和任务 2 所需版本锚。任务 2 接到可运行的离线入口及验证说明后开工。
