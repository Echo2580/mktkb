## 3. 执行步骤

1. **认证同一批次。** 以 T207 接收记录和已有独立复核为批次锚点。在受控环境核对两题所属场景、原 run 回执、完整计划 SHA、封存清单、回合绑定、当时源码和评分版本（含显式 `p2-refusal-compat/v0.6`）。用独立可信记录提供预期绑定，核对公开 source map、场景和入库身份。若 run ID 曾复用，以完整计划 SHA、场景绑定和封存回执确认本次尝试。历史工具兼容性、认证或完整性未通过时，记录实际阻断，保留原件。
2. **重建每个有关回合的完整使用来源。** 按冻结口径核对发给模型的证据、直答事实、直答引用、最终引用及其源单元身份。把每个使用单元关联到同回合数据库投影，并用该场景实际入库证明和版本映射核对文档与版本。检索候选独立记录。主张使用集为空时，须有既有契约认可的空集证明。输出为空、未见引用或检索列表缺项不足以证明使用集为空。
3. **按冻结判据判定。** 先确认原禁源引用的范围。若禁止整份文档版本，核实该文档与版本身份，并覆盖所有使用单元。若冻结范围是特定单元，再用权威的 `unit_key` 或 `locator` 定位。当前 `ForbiddenSourceIdentity` 对仅文档代号的引用会返回无法定位。可用既有身份感知离线工具核对文档和版本，但诊断输出仍需经正式证据校验。身份、定位或使用层完整性无法证实时保留 unknown。证据确认命中禁源时保留硬失败，并同时保留原禁值、应拒答及其他既有判据的结果。[源映射](../../evaluation/p2-holdout-v3.source-map.json) · [安全轴分类器](../../../backend/src/mktkb/evaluation/p2_hard_evidence.py) · [离线重评工具](../../../backend/src/mktkb/evaluation/p2_evidence_rescore.py)
4. **核验并回传安全聚合。** 保全原卡，补证结果另立记录并绑定原批次与使用的原始证据摘要。使用现有 `validate_hard_evidence_scorecard` 核对可用场景卡，使用独立可信的 run ID、配置及覆盖作为预期值。有四场景组合时再走 `validate_hard_evidence_composition`，核对原 30 题 36 回合、五个分层及其他各轴。现有整卡 `verified` 会计入 C25 的 unknown，沿用校验器实际值。若现有工具只能给出独立的离线补证摘要，或无法在保持原契约的情况下形成可验聚合，交付已经证明的事实和具体接线缺口，保持发布阻断。[组合校验](../../../backend/src/mktkb/evaluation/p2_holdout_scenarios.py)

## 4. 验收与交付

| 结果 | 判定条件 |
| --- | --- |
| `confirmed_clean` | 同批来源、全部相关回合及使用层完整，两个必需轴均按原判据证实通过。对已出具的聚合记录实际校验结果。 |
| `hard_failure_found` | 任一受查回合从同批已认证证据证实禁源、禁值命中或其他安全硬失败。如实计入补证结论。 |
| `insufficient_evidence` | 已能访问证据，但任一必需轴仍缺可信映射、定位、完整使用层或其他必要证明。报告缺项及能补齐该缺项的最小后续验证范围。 |
