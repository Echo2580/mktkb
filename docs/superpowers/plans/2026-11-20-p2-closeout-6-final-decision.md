# P2 收尾任务 6 · 经理核收与主人最终决定

**角色**　经理汇总和核收，主人作最终决定。输入为 T900 独立结论、正式总门结果、四场景安全聚合、N/C/U 证据、B0 恢复结果、资金核验和浏览器证据。[原 P2 任务书](2026-11-10-mktkb-p2-taskbook.md) · [关项和证据状态](../../reports/OBS-EVAL/P2/T209-PREP/t209-b0-closeout.md)

## 执行

1. 锁定送审候选。核对准确的分支、HEAD、未提交改动摘要、正式配置摘要、B0 ID、跨场景正式门禁输出、T900 报告版本及其对应证据。若候选发生影响判定的变更，明确受影响范围并完成定向复核。
2. 给主人一页结论。分列 B0/精确/OCR/N/C/U/H2，八项硬门禁，必需及非必需未知，有限 Ragas 结果，真实请求/费用和当前上限，档案恢复，浏览器结果及未运行项。分别标注开发、独立、真实、浏览器验证边界。若仍有失败或阻断，列具体工件、责任角色和最小返工包。
3. 请主人给出通过、保留通过、返工或改需求，并记录原话、日期、批准范围、所指候选和约束。正式质量门继续如实记录。尚有硬失败、必要未知或关键证据缺失时，维持技术门阻断；如主人决定改变要求，单列变更后的验收口径。
4. 按主人明确授权办理实际收尾动作。保留已审核工作树和发布范围，只在范围内提交、推送、合并或执行发布。记录授权和实际产物，核对最终版本、目标分支或发布状态。遇到冲突或候选变动时，重新核影响范围与对应验收结果。

**完成标准**　T201–T209 和本轮补证材料可追溯，T900 独立总判定与保护边界有实证，B0 档案可恢复，所有正式门均有状态，主人最终决定和实际办理结果已登记。记录落在 `docs/reports/OBS-EVAL/P2/p2-report.md` 与相应证据索引。若决定返工或待批，保持当前阻断和最小待办。
