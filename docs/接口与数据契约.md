# 接口与数据契约

版本：V0.1，实施前推荐稿，2026-10-27。依据需求文档 V1.3、技术方案 V0.1；与墨刀原型并行整理，尚未实现接口。

## 1. 公共约定

- API 前缀 `/api/v1`，JSON 使用 UTF-8、snake_case，业务标识使用 UUID 字符串，revision 为非负整数。
- 时间返回带时区的 ISO 8601 字符串，服务端内部按 UTC 保存，页面按 Asia/Shanghai 显示。
- 列表使用 `offset`、`limit`，默认 limit=20，上限100；响应 `{items, total, offset, limit}`。预览记录同样分页，不能一次返回全部原件正文。
- 20 MB 文件限制按20×1024×1024字节执行，图片上限20,000,000像素；PDF最多50页；Excel每文件跨可见表合计最多5,000条有效数据行，表头与空行不计入。
- 同时有效文件50份、当前有效Excel记录累计10,000条是验收负载目标，发布时记录替换后的总量用于容量观测，不自动把验收规模变成硬性拒绝阈值。3人同时在线同样是验收负载目标，不是限制只能注册3个账号。
- 客户端不传入服务器文件路径、任意远端URL或SQL。来源标识必须由服务端解析。
- 错误响应统一为 `{error: {code, message, retryable, details}, request_id}`，不含调用密钥、绝对文件路径、堆栈或完整外部请求。

## 2. 登录与权限

Cookie名称为 `mktkb_session`，会话默认8小时，服务端保存令牌摘要；HTTPS使用Secure，另设HttpOnly与SameSite=Lax。登录接口校验受信任Origin，登录后的写接口使用会话对应的 `X-CSRF-Token`；退出撤销服务端会话。

| 方法与路径 | 请求 | 响应与权限 |
| --- | --- | --- |
| POST `/auth/login` | `{username, password}` | 200 `{user, csrf_token}` 并设置Cookie；错误凭据401 |
| GET `/auth/me` | 无 | 200 `{user, csrf_token}`；未登录401 |
| POST `/auth/logout` | CSRF头 | 204，撤销会话；已退出请求可重复处理 |
| GET `/healthz` | 无 | 200 `{status:"ok"}`，不暴露业务资料或运行配置 |

User公开字段为 `id, display_name, role`；role只有admin、employee。管理员也只能查看自己的会话，不拥有浏览他人会话的默认能力。公共注册和账号管理后台不在首版范围。

## 3. 文件、版本与任务

Document与DocumentVersion分开：Document表示逻辑资料，DocumentVersion表示某次上传。新增版本不改变有效版本；不能用一个“文件状态”同时表示有效V2和处理中V3。

### 3.1 核心结构

| 结构 | 最小字段 |
| --- | --- |
| DocumentSummary | id, name, file_type, active_version, latest_version, deleted, created_at, last_published_at |
| VersionSummary | id, number, state, sha256, uploaded_at, published_at, processing_report |
| JobStatus | id, version_id, state, stage, completed_pages, total_pages, error_code, message, retryable |
| SourceUnit | id, document_id, version_id, kind, locator, text, fields, warnings |
| Locator | sheet、row、heading、paragraph、page、bbox按类型出现；页码与原始行号均从1开始 |

版本内部状态：queued、processing、review_required、failed、published、superseded、cancelled、deleted。页面文案分别为等待处理、处理中、待确认、处理失败、已生效、已被替换、已取消、已删除。“上传中”由客户端实际上传过程显示。

任务状态：queued、running、succeeded、failed、blocked、cancelled。OCR额度不足时任务blocked、版本failed，错误码明确，恢复条件后可重试；不能把blocked当作处理中无限等待。

### 3.2 文件接口（全部管理员权限）

| 方法与路径 | 关键输入 | 成功行为 |
| --- | --- | --- |
| POST `/documents` | multipart file；同名新增时显式 `allow_same_name=true` | 202 `{document, version, job}`，创建待处理版本 |
| GET `/documents` | q、file_type、state、offset、limit | 分页DocumentSummary，分别显示有效版本与最新版本 |
| GET `/documents/{document_id}` | 无 | 文件元信息及版本摘要，删除后返回必要失效元信息 |
| POST `/documents/{document_id}/versions` | multipart file；`expected_active_version_id`可空 | 202，新增替换版本，旧版仍有效 |
| GET `/jobs/{job_id}` | 无 | 200 JobStatus |
| POST `/jobs/{job_id}/retry` | 无 | 202；同一任务已在运行时409，不产生重复任务 |
| GET `/documents/{document_id}/versions/{version_id}/preview` | offset、limit、可选page/sheet | 分页SourceUnit及完整的页面/工作表处理摘要 |
| POST `/documents/{document_id}/versions/{version_id}/publish` | `{expected_active_version_id, expected_revision}` | 200 `{document_id, active_version_id, revision, published_at}` |
| POST `/documents/{document_id}/versions/{version_id}/cancel` | 无 | 204；仅取消未生效新版及其任务，不撤销旧有效版本 |
| DELETE `/documents/{document_id}` | query参数`expected_revision` | 200 `{document_id, deleted:true, revision}`，撤销有效版本并取消未完成任务 |
| GET `/documents/{document_id}/versions/{version_id}/file` | 无 | 受保护的管理员原件预览；已删除或取消内容不可读取 |

重试恢复成功检查点；如果换了文件内容，必须作为新版本重新上传，不用旧任务ID覆盖字节。

列表state筛选：published匹配当前有效版本存在，其余状态匹配最新处理版本；一份资料可能既有有效版、又有处理中新版，不能把这两种状态强行做成互斥分类。默认列表排除已删除资料。

### 3.3 冲突与幂等规则

- 同名不同内容，未显式选择新增或替换时409 `SAME_NAME_REQUIRES_ACTION`，返回可选逻辑文件摘要。
- 与现有有效或处理中版本字节相同，409 `DUPLICATE_CONTENT`；替换内容相同为409 `CONTENT_UNCHANGED`，均不创建有效新版本。已删除文件的原内容可重新导入。
- 去重检查与落库需有数据库约束/事务保护，不能只在客户端检查。
- 发布要求review_required、所有必需页成功、目标文件未删除，预期有效版本及revision仍匹配。
- 重复发布同一个已生效版本且不存在新的竞争变更，可返回原成功结果，不重复递增revision；其他过时请求409 `PUBLISH_CONFLICT`。
- 删除已删除文件返回既有删除结果，不重复递增revision；取消已取消新版返回204。
- PDF空白页必须被明确识别并记录为空页；存在图像但文本不可用不能直接当作空页跳过。

## 4. 检索与会话

| 方法与路径 | 请求或参数 | 行为 |
| --- | --- | --- |
| POST `/conversations` | `{title?: string}` | 201 `{id,title,created_at}`，属于当前用户 |
| GET `/conversations` | 分页 | 只列出本人会话 |
| GET `/conversations/{id}/messages` | 分页 | 只读本人消息，来源摘要展示当前active/superseded/deleted状态 |
| DELETE `/conversations/{id}` | 无 | 204，删除本人会话可见性及关联未完成请求，不影响知识库 |
| POST `/conversations/{id}/messages` | `{client_request_id, question}` | 完成后200 AskResult；总处理时限60秒，无事实流式输出 |
| GET `/messages/{message_id}/sources/{source_id}` | 无 | 本人消息所引用来源详情，活动来源200；失效来源410，仅必要元信息 |
| GET `/messages/{message_id}/sources/{source_id}/file` | 无 | 鉴权后返回仍有效来源原件/原图；失效来源410且无文件内容 |

question去首尾空白后长度1～2,000字符。client_request_id为UUID，同一会话内唯一；同ID同载荷重试返回既有结果，处理中返回409 `QUESTION_IN_PROGRESS`，同ID不同问题409 `REQUEST_PAYLOAD_MISMATCH`。每会话同时仅处理一个问题；请求失败后允许按原载荷明确重试，不因按钮连点重复追加消息或发起并行付费请求。

网络断开、进程退出后的外部调用计费无法保证撤销。保存请求状态与失败原因，避免无限重复调用；失败重试与业务会话内容分开记录。

### 4.1 AskResult

```json
{
  "request_id": "uuid",
  "message_id": "uuid",
  "kind": "answer",
  "text": "城东店的宣传海报位于B区1号货架第二层。",
  "revision": 3,
  "sources": [
    {
      "source_id": "uuid",
      "document_name": "物品位置表.xlsx",
      "version_number": 2,
      "status": "active",
      "locator": {"sheet": "物品位置", "row": 8},
      "published_at": "2026-10-27T02:30:00Z"
    }
  ],
  "candidates": [],
  "conflicts": [],
  "missing_fields": [],
  "error_code": null,
  "retryable": false
}
```

kind枚举：answer、clarification、not_found、conflict、service_error、knowledge_changed。以上业务结果统一返回200，前端必须判断kind；401、403、请求校验错误、资源不存在、请求处理中、服务器过载等使用HTTP错误响应。

- clarification的candidates为 `{label, followup_question}` 列表。点击后发送完整追问，不提交任意SQL或信任客户端实体判定。
- conflict的conflicts为`{field, entries:[{value, source_id}]}`列表，包含不同有效值及各自来源，不能以not_found掩盖冲突。
- 部分可答使用answer与missing_fields，已有事实仍需来源。
- service_error没有伪造来源，error_code区分模型超时和不可用；不得转换为not_found。
- knowledge_changed不保存或展示待发的旧事实答案，提示重新查询。

### 4.2 服务函数契约

以下签名用于实施任务对接；类型在相应feature的schemas/types模块定义。

跨模块类型固定如下：

- FileKind：docx/xlsx/pdf/png/jpg/jpeg；OCRMode：text/table。
- ParsedUnit：`kind, locator, text, fields, warnings`；kind为paragraph/table_row/image_text，fields保留原始表头与单元格值，locator按第3.1节定义。
- QueryIntent：`mode: record/document, terms: list[str], entity_filters: dict[str,str], requested_fields: list[str]`；实体筛选只允许store/item/store_id/item_id，使用已验证的内部映射，不能被当作任意SQL字段。
- EvidenceSet：`units: list[SourceUnit], kind: matches/ambiguous/conflict/none, total_candidates: int, revision: int, candidates: list`；候选总数不能只等于截断后的返回条数。
- SourceView：`status: active/superseded/deleted, document_name, version_number, locator`；仅active附带引用片段、字段或原图入口。
- UploadReceipt：`document, version, job`；Publication：`document_id, active_version_id, revision, published_at`；Deletion：`document_id, deleted, revision`。
- 供应商适配器实现ModelGateway.complete或OCRGateway.recognize协议；模型/OCR输入输出类型定义在providers/types.py，具体客户端持有服务端配置及HTTP依赖，不让调用方通过参数注入任意目的地址。
- CompletionInput：`purpose: query_expansion/answer, question: str, context: DialogueContext, evidence: list[ModelEvidence]`；DialogueContext只含最近最多3条用户问题与已明确实体条件，不把历史助手事实当作当前证据。ModelEvidence为`source_id, text, fields`，仅取本次有效候选。
- CompletionOutput：`text, source_ids, query_terms, provider_request_id, usage`；query_expansion只消费query_terms，answer消费text与source_ids。供应商返回的用量缺失时usage为null，不编造计费数据。解析失败或来源ID超出候选集合映射MODEL_OUTPUT_INVALID。
- OCRInput：`content: bytes, mime_type: str, page: int, bbox: tuple | None`；只含经过边界检查的本地图片内容及来源定位。OCRPageResult为`text, table_rows, regions, provider_request_id, confidence`，confidence仅在服务真实提供时使用，否则null。

| 模块 | 接口 |
| --- | --- |
| auth/service.py | `login(db, username: str, password: str) -> LoginResult`；`require_user(db, session_token: str) -> UserContext` |
| documents/service.py | `stage_upload(db, store, file: UploadInput, *, document_id: UUID | None, expected_active_version_id: UUID | None, allow_same_name: bool = False) -> UploadReceipt` |
| ingestion/parsers/types.py | `parse_document(path: Path, kind: FileKind, services: ParseServices) -> Iterator[ParsedUnit]`；每个解析器实现同一协议 |
| ingestion/worker.py | `run_one_job(db, store, parsers, *, now: datetime, ocr) -> JobRunResult`；`claim_job(db, *, now: datetime, lease_seconds: int) -> JobLease | None` |
| documents/lifecycle.py | `publish_version(db, document_id: UUID, version_id: UUID, *, expected_active_version_id: UUID | None, expected_revision: int) -> Publication`；`delete_document(db, document_id: UUID, *, expected_revision: int) -> Deletion`；`cancel_version(db, document_id: UUID, version_id: UUID) -> None` |
| retrieval/service.py | `retrieve(db, intent: QueryIntent, *, revision: int, limit: int = 20) -> EvidenceSet` |
| providers/deepseek.py | `DeepSeekClient.complete(request: CompletionInput, *, timeout_seconds: float) -> CompletionOutput`为async方法；输入仅本次问题、必要上下文及允许的证据 |
| providers/tencent_ocr.py | `TencentOCRClient.recognize(page: OCRInput, *, mode: OCRMode) -> OCRPageResult`；模式text/table，不接收任意外部URL |
| conversations/service.py | `async ask(db_factory, user: UserContext, conversation_id: UUID, request: AskRequest, *, model) -> AskResult` |
| sources/service.py | `get_message_source(db, user: UserContext, message_id: UUID, source_id: UUID) -> SourceView` |

不得让后续任务自行变换函数名或类型；契约变更时同步计划和调用方。

## 5. 事务、租约与回答提交

- stage_upload保存完整文件后才建立可领取任务；发生异常回收临时文件。暂存与数据库落库间的孤立文件由清理流程识别，不对外开放。
- worker单并发，领取租约默认120秒并每30秒续期；外部调用在写事务之外，领取及检查点提交均为短事务。租约失效的旧worker不能提交结果。
- 外部OCR调用前、结果提交前都核对任务未取消、文件未删除、版本身份未变；删除或取消不再触发下一页/重试，迟到结果丢弃。
- 发布、删除及有效版本切换在短事务内递增revision；查询必须关联当前有效版本和未删除文件，旧索引未物理清理也不可见。
- 模型生成结束后，以一个短写事务完成“对比revision→检查请求所有权/会话未删除→校验来源有效性→保存回答与引用”。提交定义为回答完成点；模型调用始终在事务外。
- 默认不做跨用户答案缓存。历史聊天只提供追问上下文，每次仍重新查询当前有效资料。

## 6. 额度与安全边界

- OCR接口默认使用GeneralAccurateOCR、RecognizeTableAccurateOCR两个适配入口，接入前核对账号实际免费包是否覆盖。
- 单worker外部OCR不超过2次/秒，429有界退避；额度不足阻塞任务，不继续自动重试或切换收费服务。
- 本地OCRCallRecord仅用于请求去重与排错，不代表全账号余额；真实免费使用需同时核对账号后付费设置。
- DeepSeek与腾讯云凭据分别保存在服务端配置；下载、来源、预览接口全部鉴权，错误与日志不暴露密钥。
- 模型输出的来源ID只能取自本次EvidenceSet；位置、电话、编号等字段由代码核对原值。文档内指令不参与系统权限判断。

## 8. 观测与监控接口（只读）

本节描述已落地的只读监控接口，前缀 `/api/v1/observability`。四个端点全部为 `GET`，全部要求管理员角色，只返回哈希、计数、长度、时长、成本、状态与聚合结果；不提供写入、删除、重跑或修改配置的入口。

### 8.1 权限与错误顺序

- 未登录：`401 AUTH_REQUIRED`；employee：`403 ROLE_REQUIRED`，`error.details.required_role` 为 `admin`；admin：`200`。
- 执行顺序固定为“鉴权 → 参数校验 → 资源读取”。未登录或 employee 即使提交非法 `window`、不存在的 `trace_id` / `run_id`，也只返回 401 / 403，不返回 404 / 422，不泄露资源是否存在。
- 错误响应沿用公共信封：`{error: {code, message, retryable, details}, request_id}`；不得包含问题/答案原文、内部 JSON、SQL、库路径或凭据。

### 8.2 端点

| 方法与路径 | 关键参数 | 成功响应 |
| --- | --- | --- |
| GET `/observability/traces/{trace_id}` | `trace_id` | 200 `{trace, spans, degraded_reason}`；单条 trace 摘要 + span 摘要；不存在 404 `TRACE_NOT_FOUND` |
| GET `/observability/requests/{request_id}/traces` | `request_id` | 200 `{request_id, traces, degraded_reason}`；同一产品请求的全部尝试摘要（`attempt` / `replayed` / `previous_trace_id`）；未知 request 返回 200 空列表 |
| GET `/observability/metrics` | `window`，默认 `24h` | 200 按 `path` / `outcome` 聚合的条数、P50/P95、token、成本、degraded/error 计数 |
| GET `/observability/runs/{run_id}` | `run_id` | 200 `{run_id, holdout_detected, details_withheld, manifest, summary, gate, degraded_reason}`；不存在 404 `RUN_NOT_FOUND` |

`trace_id` / `request_id` / `run_id` 只接受 `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`，拒绝 `..`、结尾点和路径分隔符；非法值 422（`INVALID_TRACE_ID` / `INVALID_REQUEST_ID` / `INVALID_RUN_ID`）。路径穿越在进入资源读取前被拒绝：被 id 校验拦截时为 422，未被路由匹配时为 404；均不得 200。

### 8.3 响应字段（白名单）

- `trace`（TraceSummary）：`trace_id, request_id, http_request_id, attempt, replayed, previous_trace_id, mode, scope, path, content_mode, query_kind, outcome_kind, reason, answer_source, status, error_code, latency_ms, created_at, question_hash, question_chars, hash_algo, hmac_key_id, user_id_hash, conversation_id_hash, go_decision, index_revision, manifest_sha256, pipeline_version, config_hash, span_count`。
- `spans`（SpanSummary）：`span_id, parent_span_id, name, started_at, duration_ms, status, error_code, attribute_count, attribute_keys`；只返回属性**键名与个数**，不返回 `attributes_json` 原文或属性值。
- `metrics`（MetricsResponse）：`window, since, until, total_traces, invalid_created_at_count, invalid_payload_count, groups, degraded_reason`；`groups` 每项为 `path, outcome, count, latency_samples, latency_ms_p50, latency_ms_p95, tokens_input, tokens_output, tokens_total, cost_cny, degraded_count, error_count`。
- `runs`：`manifest` 白名单含 `run_id, mode, scope, suite, dataset_version, dataset_sha256, corpus_manifest_sha256, business_date, index_revision, pipeline_version, gate_version, label_version, created_at, case_count, config_hash, holdout_details, holdout_labels_sha256, multi_turn_case_count, multi_turn_turns_executed`；`summary` 白名单含 `run_id, mode, suite, scope, dataset_version, dataset_sha256, corpus_manifest_sha256, business_date, index_revision, pipeline_version, gate_version, case_count, scored_count, skipped_ocr_count, error_count, status_counts, metrics, retrieval_only, holdout`；`gate` 白名单含 `exit_code, run_id, suite, mode, gate_version, scored_count, min_sample, hard_failures, gate_status, failure_count, unknown_count, not_applicable_count, warnings_count, quality_status`。
- `holdout` 只含 `aggregate_only, details_written, label_version, questions_sha256, labels_sha256, strata, metadata_mismatch_count, traces_persisted`；不返回逐题 `cases.jsonl`、题干、答案或审计正文。
- 不返回 `dataset_path`、`corpus_dir`、`trace_store`、`database_url` 等路径/配置字段，也不返回任何 `*_json` 原文。

### 8.4 时间窗与分页

`window` 只接受 `^([1-9][0-9]{0,5})([hm])$`：正整数的 `h` 或 `m`，最多 6 位。默认 `24h`。合法示例：`1h`、`24h`、`30m`、`999999h`；非法示例：`0h`、`-1h`、`abc`、`24`、`1.5h`、`24D`、`1H`、带前导空白的值、7 位整数，均返回 422 `INVALID_WINDOW`。超大窗口只保证不崩溃（200），不声称已验证性能或全表保护上限。

四个端点均**无分页参数**（无 `limit` / `offset`，响应也无 `total/offset/limit` 分页结构）：分页边界为 NOT-APPLICABLE，见 OpenAPI 快照。`metrics` 返回窗口内全部聚合，`traces`/`runs` 按单个资源返回完整白名单字段。

### 8.5 降级

- Trace 关闭（`app.state.trace_repo is None`）：四个端点均 200；`traces` 返回 `{trace: null, spans: [], degraded_reason: "trace_disabled"}`，`requests` / `metrics` 返回空聚合 + `trace_disabled`，`runs` 仍返回 manifest/summary/gate 聚合并附该原因。
- 仓储不可用：trace 相关端点 200 + `trace_unavailable`，不 500。
- `metrics` 遇到不可解析的 `created_at` 或指标 JSON：200 + `partial_data`，同时给出 `invalid_created_at_count` / `invalid_payload_count`。
- `runs` 的 manifest/summary/gate：manifest 缺失 404 `RUN_NOT_FOUND`；summary / gate 缺失时对应字段为 `null`，不单独降级；任一 JSON 解析失败时 200 + `manifest_invalid` / `summary_invalid` / `gate_invalid`（取首个原因），不 500。
- Holdout run（`suite=holdout` 或 `holdout_details=true`）：只返回聚合；`holdout_detected=true`，存在逐题明细或声明时 `details_withheld=true`，逐题详情不可通过本组端点获取。

### 8.6 只读与不泄露

- 只读声明：本组端点仅注册 `GET`；无 POST/PUT/PATCH/DELETE；不写业务库、Trace 库或评测产物，不改变评测 run、Holdout、账本或配置。评测 run 只读 `settings.data_dir/eval/runs/<run_id>` 下的 `run_manifest.json` / `summary.json` / `gate.json`。
- 不泄露：成功与错误响应（401/403/404/422）均不得包含问题/答案/上下文原文、`*_text` 正文字段、`*_json` 原文、属性值、Holdout 逐题/题干/答案、SQL、库路径或凭据。对外只给哈希、计数、长度、时长、成本、状态与聚合一类字段。
- OpenAPI 以 `401` / `403` 响应声明本组端点的权限；应用使用 Cookie 会话（`mktkb_session`），当前未额外声明 `securitySchemes`，运行期鉴权由服务端 `require_role("admin")` 依赖执行，不依赖页面隐藏。OpenAPI 快照见 `docs/reports/OBS-EVAL/P1/evidence/T114/openapi-observability.json`（仅含 4 条路径与相关 components 子集）。
